# Milestone v0.4 — Language Expansion

## Goal

Repo Lens の Analyzer Provider 構造を実証し、Java / Kotlin 以外の言語へ構造解析を拡張する。第一対象は **JavaScript / TypeScript** とする。

v0.4 の目的は対応言語数を増やすことだけではなく、特定言語へ強く依存せず Analyzer を追加できる拡張モデルを完成させることである。

## Deliverables

### Provider architecture

- 言語別 Analyzer Provider の明確な SPI
- Provider の availability 判定
- 言語 plugin が存在しない環境でも Repo Lens 本体が動作する構造
- Analyzer ID / Finding schema / Settings の共通化
- Provider ごとの capability 表示

### JavaScript / TypeScript

最低限、以下の構造チェックを対象とする。

- Large Class 相当
- Large Function / Method
- Too Many Parameters
- Deep Nesting

Large File / TODO-FIXME 等の Tier 0 Analyzer は既存実装をそのまま利用する。

JavaScript / TypeScript の PSI / language API は利用可能な Public API を優先し、内部 API への依存は避ける。Java/Kotlin と意味が異なる構文を無理に同一判定へ押し込まず、Provider 側で差異を吸収する。

### Capability model

Tool Window または Settings から、現在の環境で各言語について何が解析可能か確認できるようにする。

例:

| Language | Tier 0 | Structure | Reference | Dependency |
|---|---|---|---|---|
| Java | Yes | Yes | Yes | Yes |
| Kotlin | Yes | Yes | Yes | Yes |
| JavaScript | Yes | Yes | Limited | Limited |
| TypeScript | Yes | Yes | Limited | Limited |

### Copy / Navigation consistency

新しい Provider でも以下の UX を維持する。

- 同じ Finding list に表示
- 同じ Severity / filter 操作
- file / symbol / range Navigation
- Copy Result
- Copy with Code
- Copy for AI

Provider 固有情報が必要な場合は `metadata` と Detail 表示で補足し、共通フォーマットを破壊しない。

### Provider diagnostics

- Analyzer が利用できない理由を表示できる
- 必要な language plugin がない場合をエラー扱いしない
- Unsupported syntax は安全に skip する
- Provider 単位の解析時間をログで確認可能にする

## Acceptance Criteria

- [ ] Language Analyzer Provider を追加できる明確な SPI がある
- [ ] JavaScript / TypeScript Provider が実装されている
- [ ] JS/TS の function / method size を検出できる
- [ ] JS/TS の parameter count を検出できる
- [ ] JS/TS の nesting を検出できる
- [ ] Tier 0 Analyzer と言語別 Analyzer の結果が同じ UI に統合される
- [ ] Finding から JS/TS の対象位置へ Navigation できる
- [ ] Copy for AI が Java/Kotlin と同じ基本形式で動作する
- [ ] language plugin が利用できない環境でも Repo Lens 本体を起動できる
- [ ] Provider capability をユーザーが確認できる
- [ ] v0.3 までの主要機能が回帰していない
- [ ] Plugin Verifier と対象 IDE の smoke test が通る

## Test focus

- JavaScript function / class / arrow function
- TypeScript class / method / interface 周辺
- nested callback / lambda 相当
- JSX / TSX を含む fixture
- unsupported syntax の安全な skip
- provider plugin の有無
- Java/Kotlin と JS/TS が混在する project

## Optional work

v0.4 の必須条件を満たした後、実装コストと Public API の安定性を見て以下を検討する。

- Go Provider
- Python Provider
- その他 JetBrains IDE / language plugin への展開

これらは v0.4 完了条件には含めない。

## Non-goals

- 全言語で完全に同じ解析精度を保証すること
- 独自 parser の大量実装
- IDE 内の全 language plugin への一括対応
- Provider ごとの独自 UI を増殖させること

## Exit review

Java/Kotlin と JS/TS が混在する実 Repository で使用し、Provider architecture が追加言語に耐えられることを確認する。新言語追加時に core / UI の大幅変更が必要なら、v1.0 前に SPI を再整理する。
