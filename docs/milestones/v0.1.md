# Milestone v0.1 — Core Review Workflow

## Goal

Repo Lens の最初の実用版として、**Analyze → Findings → Navigate → Copy for AI** の縦のワークフローを完成させる。高度な解析よりも、日常のコードレビューで使える操作性と今後の拡張基盤を優先する。

## User outcome

ユーザーは IntelliJ IDEA 上で Scope を選択して解析し、レビュー候補を一覧で確認し、対象コードへ移動し、単一または複数の Finding を Markdown としてコピーできる。

## Deliverables

### Platform / architecture

- Kotlin + IntelliJ Platform Plugin の基本構成
- Repo Lens Tool Window
- Project Settings
- `Finding` / `SourceLocation` / `AnalysisRequest`
- `RepoLensAnalyzer` SPI
- `AnalyzerRegistry`
- `AnalysisOrchestrator`
- Finding の stable ID / dedup

### Analysis scopes

- Current File
- Selected Files
- Module
- Project
- Local Changes

### MVP analyzers

| ID | Check | Default threshold |
|---|---|---:|
| RL-F001 | Large File | 800 lines |
| RL-C001 | Large Class | 500 lines |
| RL-M001 | Large Method | 80 lines |
| RL-M002 | Too Many Parameters | 7 parameters |
| RL-M003 | Deep Nesting | depth 5 |
| RL-T001 | TODO / FIXME | marker presence |

Large File と TODO/FIXME は可能な限り言語非依存で動作させる。Class / Method / Parameters / Nesting は Java / Kotlin を対象に UAST を中心として実装する。

### Tool Window

- Scope selector
- Analyze / Stop
- Search
- Severity filter
- Check filter
- Findings count
- Findings table
- Detail pane
- Code preview

Finding table では最低限 `Severity / Check / File / Symbol / Location / Value / Threshold` を確認できること。

### Navigation

- Single click で Detail 更新
- Double click / Enter で Editor へ移動
- 対象行へ移動
- 可能な場合は対象 range / symbol を選択

### Clipboard

- Copy Result
- Copy with Code
- Copy for AI
- Multi-select
- Project-relative path
- Context lines
- Code snippet 上限と truncation 表示

AI Provider 固有処理は持たず、任意の AI チャット等へ貼り付けられる Markdown を生成する。

### Settings

- Analyzer enable / disable
- Thresholds
- Exclude glob / regex
- TODO markers
- Test / generated source の扱い
- Copy settings

## Implementation order

1. Plugin skeleton / Tool Window / Settings skeleton
2. Domain model / Analyzer SPI / Orchestrator
3. Current File / Project Scope
4. Large File / TODO-FIXME
5. Findings table / Detail / Navigation
6. Copy for AI
7. Java/Kotlin UAST analyzers
8. Selected Files / Module / Local Changes
9. Cancellation / Dumb Mode / performance tuning
10. Tests / Plugin Verifier / real repository smoke test

最初の内部チェックポイントでは `Project → Analyze → Large File/TODO → Findings → Navigation → Copy for AI` だけを先に完成させる。

## Acceptance Criteria

- [ ] Tool Window を開ける
- [ ] 5種類の Scope が利用できる
- [ ] 6 Analyzer が設定値に従って Finding を生成する
- [ ] Java / Kotlin の UAST Analyzer が動作する
- [ ] Unsupported language でも Tier 0 Analyzer は利用できる
- [ ] Finding に file path / line / symbol / reason / metric が含まれる
- [ ] Finding から Editor の対象位置へ移動できる
- [ ] 検索・Severity・Check filter が動作する
- [ ] 複数 Finding を一つの Markdown としてコピーできる
- [ ] code snippet 上限と truncation が機能する
- [ ] Settings が project ごとに保持される
- [ ] Analysis をキャンセルできる
- [ ] Indexing 中の制限を UI で説明できる
- [ ] Editor を長時間ブロックしない
- [ ] ソースコードの自動外部送信を行わない
- [ ] Unit / fixture / smoke test が通る
- [ ] Plugin Verifier に重大な互換性エラーがない

## Non-goals

- Unused Candidate
- Circular Dependency
- Branch Diff / Git history / Hotspot
- JavaScript / TypeScript の構造解析保証
- 自動修正
- AI チャット UI
- 外部サーバー / チーム共有

## Exit review

v0.1 完了後は実 Repository で複数回利用し、Finding のノイズ量、Local Changes の有効性、Copy for AI の情報量、Navigation の速度、UAST の誤検出を確認する。重大な UX / performance 問題があれば、v0.2 の機能追加より先に修正する。
