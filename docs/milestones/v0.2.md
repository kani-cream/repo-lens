# Milestone v0.2 — Structural Analysis

## Goal

v0.1 の操作基盤へ、参照関係と依存構造に基づくレビュー候補を追加する。主対象は `Unused Candidate`、`Circular Dependency`、`ignore / suppress` とする。

## Deliverables

### Unused Candidate

- Java / Kotlin を優先対象とする
- IntelliJ の参照解決や既存 Inspection を可能な範囲で利用する
- Finding 名は `Unused Candidate` とし、未使用と断定しない
- symbol、参照状況、判定理由、confidence を保持できるようにする
- Reflection、DI、Framework、Serialization 等で判定に限界があることを Detail と Copy 出力へ明示する

### Circular Dependency

- package / module 粒度から開始する
- dependency graph を構築する
- cycle を検出して Finding として表示する
- cycle path を Detail で確認できる
- 関連箇所へ Navigation できる
- Copy for AI に dependency path を含める

class-level の依存循環は必須範囲に含めず、package / module 粒度の実用性を確認してから判断する。

### Ignore / suppress

- Finding 単位の Ignore
- Rule + path / symbol pattern による Suppress
- Settings から管理できる
- Stable Finding key を利用する
- 設定変更後の再解析へ反映する
- ignored Finding の表示切替を可能にする

### UI

- confidence を表示可能にする
- reference evidence / dependency path を Detail で表示する
- ignored Findings の表示切替を追加する
- Analyzer の制約説明を表示できるようにする

## Performance

- Indexing 状態を考慮する
- Cancellation を維持する
- 参照解析で Editor を長時間ブロックしない
- dependency graph のメモリ使用量を大規模 fixture で確認する
- キャッシュは必要性を確認してから最小限導入する

## Acceptance Criteria

- [x] Java / Kotlin で Unused Candidate を検出できる
- [x] Candidate 判定の不確実性を UI と Copy 出力で確認できる
- [x] package / module の Circular Dependency を検出できる（package 粒度で実装。module 粒度は Gradle/Maven がビルドレベルで循環を防ぐため必要性を確認してから追加する）
- [x] cycle path を確認できる
- [x] cycle の関連箇所へ Navigation できる
- [x] Finding を Ignore できる
- [x] path / symbol pattern で Suppress できる
- [x] ignore / suppress 設定が project ごとに保持される
- [x] ignored Findings の表示切替ができる
- [x] Indexing 中の制限が適切に扱われる
- [x] v0.1 の主要ワークフローが回帰していない
- [x] Unit / fixture / integration test が通る
- [x] Plugin Verifier に重大な互換性エラーがない

## 完了記録（2026-08-15）

全 Acceptance Criteria を満たし、v0.2 を完了とする。実装は PR #13〜#15
（Ignore / Suppress、Circular Dependency、Unused Candidate）。

検証状況:

- 自動検証: :core 89 / :plugin 51 fixture tests（参照解決・Dumb Mode skip・
  Kotlin candidate を含む）、Plugin Verifier で両ターゲット Compatible
- 手動検証: samples/ で Ignore / Show ignored / Suppress ルール、循環の
  path・evidence・Navigation、Unused Candidate の confidence と限界説明を確認。
  Ignore とルールの永続化は実際の設定ファイルと突き合わせ、IDE 再起動を跨いで確認。
  陰性対照（相互参照する Alpha/Beta が Unused に出ないこと）も確認

実地確認から出た修正:

- 抑制件数の表示を「N hidden (x ignored, y by rules)」へ分解（PR #13）
- Kotlin light method の合成 nullability 注釈が全 Kotlin 関数を
  entry point 扱いにしていた問題を修正（PR #15）

既知の制約:

- Circular Dependency は import 由来の辺のみ（FQN 直書きや reflection は不検出）
- Unused Candidate は public 宣言のみを対象とし、Confidence は一律 Low
- Indexing skip の GUI 表示は fixture test で担保（実操作ではインデックスが
  速すぎて再現せず）

Exit review の残課題: Unused Candidate / Circular Dependency のノイズ量評価は
Java/Kotlin 主体の実 Repository が手元に少なく（実利用対象は Go/TS 中心）、
本格評価は Java/Kotlin プロジェクトでの利用開始後に行う。Repo Lens 自身
（Kotlin）への適用が当面の評価材料となる。

- 参照あり / 参照なしの fixture
- framework 利用を想定した Candidate の注意表示
- package cycle `A → B → C → A`
- cycle のない graph
- ignore key の安定性
- suppress pattern の適用
- cancellation

## Non-goals

- Branch Diff
- Git history / Hotspot
- JavaScript / TypeScript の構造解析
- class-level dependency graph の完全対応
- 自動修正

## Exit review

実 Repository で Unused Candidate のノイズ量と Circular Dependency の粒度を確認する。ノイズが多い場合は Analyzer 追加より、confidence、evidence、ignore / suppress の改善を優先する。
