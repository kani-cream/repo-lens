# Milestone v0.3 — Git-aware Review

## Goal

Repo Lens を単なるコード構造ビューから、**変更内容と変更履歴を考慮してレビュー優先度を判断できるツール**へ拡張する。

## Deliverables

### Branch Diff Scope

- base branch と現在 branch の差分を Scope として選択可能にする
- 変更ファイルだけを解析対象にできる
- added / modified / deleted の状態を識別する
- base branch が取得できない場合は理由を表示する

### Large Diff

- ファイル単位の追加・削除行数を取得する
- configurable threshold を超えた変更を Finding として表示する
- Detail で changed lines を確認できる
- Copy for AI に diff metrics を含める

### Git history metrics

- Change frequency
- Author count
- 最終更新時点
- TODO/FIXME の経過情報を取得可能な構造

履歴情報は「品質の良し悪し」を断定するためではなく、レビュー優先度を決める Evidence として扱う。

### Long-lived TODO

- TODO/FIXME Finding と Git history を関連付ける
- 最終更新または導入時点を可能な範囲で取得する
- 一定期間以上残っている Marker をレビュー候補として識別できる
- Git 情報を取得できない場合は通常の TODO/FIXME Finding として扱う

### Hotspot

初期定義は次の組み合わせを基本とする。

- 変更頻度が高い
- 構造的 Finding が存在する
- 必要に応じ diff size / author count を補助指標とする

Hotspot score は説明可能であることを優先し、ブラックボックスなスコアリングにしない。Detail ではスコアの構成要素を確認できるようにする。

### UI

- Scope に Branch Diff を追加
- Git metrics 用の列または Detail section
- Hotspot filter / sort
- changed files の状態表示
- Git 情報が利用できない場合の明示

## Performance

Git history の全件走査を毎回行わない。対象 Scope と必要期間を限定し、同一解析内で重複 query を避ける。

大規模 Repository では以下を確認する。

- Branch Diff の応答性
- history query の所要時間
- cancellation
- partial result
- Repository サイズに応じた上限や設定の必要性

## Acceptance Criteria

- [ ] Branch Diff Scope を選択できる
- [ ] base branch との差分ファイルを解析できる
- [ ] Large Diff Finding を生成できる
- [ ] changed lines が Finding へ含まれる
- [ ] Change frequency を取得できる
- [ ] Author count を取得できる
- [ ] Long-lived TODO の経過情報を表示できる
- [ ] Hotspot を算出し、構成根拠を説明できる
- [ ] Hotspot から対象ファイルへ Navigation できる
- [ ] Copy for AI に必要な Git metrics を含められる
- [ ] VCS 未設定時も v0.1/v0.2 の非Git機能を利用できる
- [ ] Git 解析をキャンセルできる
- [ ] v0.2 までの主要機能が回帰していない
- [ ] Plugin Verifier と主要テストが通る

## Test focus

- base / feature branch の差分 fixture
- rename を含む差分
- large diff threshold
- 履歴の少ない / 多いファイル
- 複数 author
- TODO の履歴情報
- Hotspot score の再現性
- VCS 未設定 project

## Non-goals

- Remote GitHub API 連携
- Pull Request API 連携
- CI 結果取得
- Review comment 投稿
- JavaScript / TypeScript 構造解析の拡張
- 複雑な機械学習ベースの risk score

## Exit review

実レビューで「変更量・変更頻度・構造的 Finding」を組み合わせることで、見るべきファイルを絞れるか評価する。Hotspot が単なる派手な数字になっている場合は、v0.4 より先に Evidence 表示とスコア定義を改善する。
